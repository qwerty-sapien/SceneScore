`RagtmCandidatePort` is a new Python port of the frontend candidate statistics in `frontend/src/hooks/useBCIStream.ts`. It preserves the original defaults: alpha .02; amplitude minimum 50 uV; absolute-deviation floor 7 uV; score threshold 4; cooldown 250 ms; round(rate × one second) warmup samples; frontal channel name selection with first-two fallback and up to two required channels. Each sample computes its score before updating the mean/deviation, then increments warmup before testing. The score is not a probability. The old frontend does not directly gate this condition on railed flags. The port deliberately preserves this limitation as a comparator, and must never directly issue a SceneScore control.

`tests/ragtm_oracle.mjs` wraps **verbatim processing statements** extracted from the supplied frontend in a small Node harness. A test compares all 1,500 decisions on fixed-seed synthetic filtered samples with the Python port. This establishes the tested numerical candidate subset only. The test does not establish scientific accuracy, real replay equivalence, frontend lifecycle/configuration equivalence, or complete acquisition/filter equivalence.

The original backend's `backend/eeg/services/muse_stream_service.py` uses Muse-v1 registry configuration, an existing LSL source, five seconds of rolling storage, detrending, 50 Hz environmental-noise removal and 1–50 Hz order-2 Butterworth buffer filtering. It takes the newest filtered segment after refiltering the buffer, omits warmup rows from the recorded loop, formats LSL timestamps as Unix time, and can upload at exit if configured. SceneScore does **not** execute this backend or copy these problematic clock/upload behaviours. Raw old CSV alone cannot establish identical filtered values or independently verified blink intent. The source declares TP9/AF7/AF8/TP10 and 256 Hz; those declarations do not verify this owner's headset.

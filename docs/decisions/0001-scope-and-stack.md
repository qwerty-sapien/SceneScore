# ADR 0001 — scope and local stack

Status: accepted documentation design, 2026-09-11; runtime pins pending Phase 1 compatibility evidence.

Select React/Vite TypeScript and Web Audio; small FastAPI/WebSocket Python service; installed Blender interpreter; versioned JSON Schema with cross-language fixture conformance. NumPy/SciPy/scikit-learn are candidate numerical tools; Muse transport remains contingent on verified hardware. Browser transport owns musical time; explicit clock adapters join scene and acquisition. Approvals bind to plan/input hashes. VISION defines signed Z-motion policy and default double-only modulation.

Reject a cloud-dependent audio loop, opaque generated soundtrack as sole representation, indiscriminate pitch shifting, game/stress detection, database/GPU/Kubernetes requirements, broad multi-agent framework and copying RAGTM's dependency stack. They add scope or violate deterministic editable local performance. The existing RAGTM snapshot is an external, unchanged source reference, not SceneScore application code.

Reconsider stack only with demonstrated compatibility/latency/access failure and a smaller supported alternative, recorded evidence, migration and affected tests. Reconsider product defaults only through an explicit product decision; workers may not silently change them. Threshold changes require development evidence, locked evaluation protocol and integrator review, never final-test tuning.

The five-hour goal assumes organizer-permitted preparation. If prohibited, reduce event work to one scene/score and calibrated deterministic detector; do not promise multi-session research in that window. No preparation permission has yet been verified.

Change record: during Phase 0, user supplied RAGTM archive and requested Desktop establishment. LINEAGE now records source evidence; live performance and independent labels remain unverified. This does not authorize subsequent implementation phases.

# Video catalog — user-directed continuation, 2026-09-13

## Scope and decision

The user selected the Blender-sidecar requirement and clarified that the experience should primarily be a video catalog where users choose any available video to watch and listen. This authorizes the local catalog, prepared-pair import and player simplification implemented here. It does not authorize cloud publishing, arbitrary-video model inference, a Phase 4 release, or approval on the user's behalf.

The default route is now a searchable gallery grouped by animation, with soundtrack variants inside the selected player. The existing cream/terracotta visual language and actual animation previews are retained; video selection and listening are primary, while conducting and diagnostics are secondary. Responsive layout was inspected at 1440 and 390 pixels. The frontend and audiovisual integration skills informed the layout, real browser checks, audio-clock preservation and explicit separation of audition from human approval.

## Implementation and contract impact

- `apps/web/tools/catalog.mjs`: checks existing prepared catalogs and media and produces a small browse index; `predev`/`prebuild` invoke it. No new animation or score is generated by indexing.
- `apps/web/src/library/`: searchable catalog, source filter, grouped soundtrack versions, exact MP4/sidecar import and local IndexedDB persistence/removal.
- `apps/web/src/main.tsx`: gallery entry point, draft Watch & listen, independent music/Foley switches, exact source download, loading/error handling and player teardown. Legacy direct music/review views and formal approval controls remain.
- `apps/web/tools/prepare.py`: adds exact score/composition source-byte fields to newly prepared bundles. The normal demo preparation refreshed the matching `riff-studio` bundles and catalog hashes; authored video/music/event content is unchanged.
- `packages/audio/tests/catalog-import.test.ts`: five tests cover original-byte retention, changed/mismatched inputs, malformed/unsupported input, size limits and duplicate score IDs.
- `apps/web/tools/check-library.mjs`: real browser smoke test with screenshots and OfflineAudioContext measurements.

Frozen shared schemas/locks and evaluation thresholds are unchanged. The `video-library-1` browse index is an app-local format. `studio-bundle-1` gains optional existing-style source-byte bindings, with a verified legacy composition serialization fallback. Imported files are never treated as approved and their embedded paths are not fetched. Original files remain untouched when a local browser copy is removed.

The existing preparation and playback limits remain: 120-second scenes and bounded event/polyphony scheduling. Import adds 64 MiB JSON, 256 MiB MP4 and 12-item / 512 MiB local storage limits. A plain video or raw Blender sidecar is insufficient; the prepared sidecar must carry the scene, score, effects and binding data. Storage is per browser/origin. Offline playback after loading is supported, not a cold offline site launch.

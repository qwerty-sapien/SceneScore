# Shared guardrails

## Authority, scope and truthful evidence

Prefer the smallest coherent architectural change that fixes the production failure. Preserve useful contracts, process isolation, path safety and provenance. Refactor obsolete assumptions when necessary; do not preserve broken choreography merely to keep tests green. Keep legacy synthetic fixtures identifiable and migrate consumers explicitly. New physical animation is still synthetic media, with its simulation provenance stated honestly.

Do not present schema validity, hashes, generator/validator agreement, sampled stills or a model's confidence as physical or aesthetic validation. Distinguish observed facts, theoretical reference expectations and creative judgments. Every gate names the exact asset/config/source identities it assessed. Re-rendering or changing dynamics invalidates the affected downstream approvals and reports.

## Tool division

Use installed Blender through CLI and Blender's own Python for build, bake, evaluated-state extraction and rendering. Use the requested `ahujasid/blender-mcp` for scene inspection, viewport/camera review and bounded interactive experiments. GUI computer use is a fallback for setup or visual inspection that lacks an adequate API.

All durable changes must be reproduced by checked-in source or explicitly managed assets. A successful MCP edit that exists only in an unsaved session is incomplete. A headless production run must not require the interactive MCP socket. Keep expensive renders/bakes outside long blocking MCP calls. Verify installed versions and capabilities rather than copying version-sensitive API names from memory.

Use trusted project-scoped MCP configuration where supported. Keep the addon bound to loopback, disable unnecessary external asset integrations and telemetry, and use upstream safe mode where available. Safe mode is defense in depth, not a security guarantee. Do not weaken host approval controls, expose the socket publicly, install unreviewed startup scripts or change global Codex settings. Pin compatible addon/server revisions and record them. Human installation/restart requirements are honest blockers for that track, not grounds to claim it ran.

## Motion and mechanics

Every important movement has a visible or established cause: support, release, impact, gravity, friction, a mechanism or an agent. Author character anticipation/follow-through and driven mechanisms intentionally; use suitable physics or independently validated analytic motion for unpowered rigid bodies. Identify the motion mode explicitly. No hand-keyframed collapse masquerading as simulated dynamics.

No conspicuous solid interpenetration, tunnelling, unsupported hovering, unjustified scale changes, energy creation or teleports. A contact solver may have small numerical penetration; define justified scale-aware tolerance and convergence checks. Do not require mathematical zero error from a numerical simulation.

Do not impose incorrect blanket rules. Constant horizontal velocity is valid in ideal ballistic motion. Zero projectile recoil can be valid for some collisions. Screen-space size and world-space size differ. A rotating rigid body's world AABB changes even when its shape does not. Validate the actual physical assumptions and rendering evidence.

Do not stretch normalized trajectories over a long duration or insert arbitrary easing into ballistic flight. Preserve physical units, release continuity and a coherent clock. Budget runtime through staging and editing, or an explicit consistently retimed presentation with regenerated timestamps. Never independently retime video and event data.

## Independent gates

Run analytic positive controls, intentionally invalid negative controls and real candidate checks. Read evaluated geometry/transforms from the finalized simulation; checking configuration flags alone is insufficient. Do not let a test derive expected trajectories from the same recipe it evaluates. Frame-rate conversion, duplicated frames or blur cannot repair bad motion.

Review native-cadence full clips plus event-centered frame windows, a neutral material/contact diagnostic pass, and the beauty render. Include off-camera collisions that could affect visible motion. Automatic checks support visual judgment; they cannot certify taste. Require an honest unverified status when full-motion perception is unavailable.

## SceneScore continuity

Keep IDs stable where semantics persist. Explicitly distinguish physical participants, passive supports, scenery and scored objects. Adding a room or character must not accidentally create a musical voice or quadratically flood interaction events. Never exclude a physically consequential collider just because it is silent.

Derive contact/Foley timing from the new evaluated animation. Maintain the existing clock/unit/quaternion conventions or perform a versioned migration. Preserve musical identities and approval semantics. Retire stale copies from active use, but preserve frozen prior evidence. A changed scene cannot inherit approval of an older scene/plan hash.

## Resource discipline

Reuse owned process/time-budget helpers where sound. Render low-resolution motion at final cadence first; only spend final-quality compute after the motion gate. Use unique output directories, bounded jobs, recorded PIDs and cleanup of task-owned children only. Never silently publish a low-cadence smoke render as the final video.

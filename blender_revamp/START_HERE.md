## Ownership and coordination

The coordinator alone changes shared schemas, root build/lock/configuration files, common manifests, migrations and authoritative status. Workers edit only agreed scopes and produce a concise handoff with changed files, commands, outcomes, artifact identities and blockers. One owner controls a live Blender/MCP session and a mutable `.blend` at a time. Never concurrently rebuild a shared cache or output directory. Separate worktrees are useful where the repository supports them; no manufactured subagent/tool invocation.

If a worker needs another scope, request the change with rationale rather than silently editing it. Once discovered, pass workers only the relevant contract, evidence, prompt and dependencies. Do not dump the whole pack into every worker.

## Completion rule

A complete result requires all mandatory gates to pass for the exact candidate delivered: generation reproducibility, physical validity, story legibility, visual quality, media decoding and SceneScore integration. Record automated, model-visual and human judgments separately. Missing perceptual access means that perceptual gate remains unverified, even when objective checks pass.

Deliver a new, unapproved draft when human plan approval is absent. Do not claim the entire product is release-ready merely because the animation milestone passes. Provide exact commands to reproduce the outputs and to resume any blocked node. Do not stop after writing the plan when implementation can proceed.

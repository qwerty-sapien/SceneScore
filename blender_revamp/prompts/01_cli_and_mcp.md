# 01: make production reproducible and interactive inspection usable

Depends on 00. Own only the agreed tooling scope; request coordinator changes to root configuration.

1. Verify the actual Blender executable and build, its bundled Python, render capabilities and FFmpeg/FFprobe. Respect the existing host profile, then verify the task-specific executable. Do not treat the snapshot's recorded version as proof that it is installed now. Keep server Python separate from Blender Python.
2. Extend the existing bounded CLI path for distinct build, bake, export, diagnostic-preview and final-render operations where appropriate. Discover names/interfaces from the repo. Separate simulation resolution from output cadence and geometry-sampling density. The present `--substeps` performs export sampling; adding more of it does not create a dynamics solver. Stop unconditionally forcing preview settings in production batches.
3. Configure the requested upstream blender-mcp using its current primary documentation and a reviewed pinned addon/server pair. Prefer a trusted project `.codex/config.toml`, preserve unrelated configuration, keep the socket on loopback and one live scene owner. Disable telemetry in the relevant server/addon settings; enable upstream safe mode when supported. Do not bypass restrictions to run arbitrary host code. Leave external generators/downloads off unless genuinely needed and authorized.
4. Prove MCP works with a bounded inspection and disposable object create/inspect/delete exercise in an owned scratch scene. Capture an actual viewport image where supported. Restore the scene and record tool names, response status and addon/server revisions. Merely adding config is insufficient. On missing trust/install/restart access, report the exact prerequisite and continue independent CLI work while marking MCP verification blocked.
5. Prove CLI generation works without MCP: small scene, deterministic inputs, saved file, bake/cache where relevant, fresh-process reopen, state export and short native-cadence render. Record executed commands and file identities. An illustrative CLI pattern is `"$BLENDER_BIN" --background --factory-startup --python-exit-code 1 --python <trusted_repo_entrypoint> -- <repo_arguments>`; adapt to the actual program and load/save order.

Use existing process cleanup, cancellation and provenance facilities where sound. Do not run large renders synchronously through the interactive MCP socket. Deliver a tested runbook and smoke evidence with separate CLI and MCP statuses. No claim of final animation quality belongs in this task.
